# ИИ-ассистент продаж + симулятор покупателей

Рабочий прототип для вымышленного цветочного магазина «Лепесток» (Москва):

- **Песочница** — веб-страница, где можно поговорить с ИИ-ассистентом магазина как покупатель,
  посмотреть собранные заявки и сводки для менеджера.
- **Симулятор** — 30 ИИ-покупателей разговаривают с ассистентом, Судья оценивает каждый диалог,
  Аналитик пишет, что исправить. Можно сравнить две версии (A/B), например «со скидкой на второй букет».

Как устроен ассистент: **Продавец** (модель) пишет черновик → **Контролёр** (без модели, по правилам)
проверяет, что нет выдуманных цен, скидок и контактов → **Диспетчер эскалации** решает, звать ли
человека, и пишет сводку → **CRM-клерк** сохраняет заявку в SQLite.

Документы: исследование рынка — `reports/`, спецификация — `docs/superpowers/specs/`, план — `docs/superpowers/plans/`.

## Установка

```bash
python -m pip install -e ".[dev]"
python -m pytest -q          # тесты не ходят в сеть
```

## Подключение модели

Ключи берутся только из переменных окружения и никуда не записываются.

| Переменная | Что это |
|---|---|
| `LLM_PROVIDER` | `gigachat` (по умолчанию) или `yandex` |
| `GIGACHAT_AUTH_KEY` | ключ авторизации GigaChat (Base64 из личного кабинета) |
| `GIGACHAT_SCOPE` | необязательно, по умолчанию `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | необязательно, по умолчанию `GigaChat` |
| `GIGACHAT_CA_BUNDLE` | путь к сертификату НУЦ Минцифры (`russian_trusted_root_ca.pem`), если система ему не доверяет |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | ключ и каталог Yandex Cloud для YandexGPT |
| `LLM_PROVIDER_CUSTOMER`, `LLM_PROVIDER_JUDGE` | необязательно: другой провайдер для покупателей или Судьи |

Серверы GigaChat используют сертификат российского удостоверяющего центра. Скачайте корневой
сертификат с https://www.gosuslugi.ru/crt и укажите путь в `GIGACHAT_CA_BUNDLE` —
проверку TLS отключать не нужно.

Без ключа всё запускается, но честно пишет «модель не подключена»; выдуманных результатов не показывает.

## Песочница

```bash
uvicorn salesai.web.app:app --reload
# откройте http://127.0.0.1:8000
```

Слева — чат, справа — вкладки «Заявки» и «Симуляция». Заявки хранятся в `data/sandbox.db`.

## Симуляция из командной строки

```bash
# 30 покупателей, до 8 реплик в диалоге
python -m salesai.sim.cli --company companies/flower_shop --personas 30 --max-turns 8

# A/B: текущая версия против варианта со скидкой на второй букет
python -m salesai.sim.cli --personas 30 --variant companies/flower_shop/variants/promo_second_bouquet.json
```

Отчёт сохраняется в `reports/sim/` (Markdown для чтения и JSON с сырыми данными), путь печатается в конце.
Без ключа команда завершается с кодом 2 и объяснением.

## Данные магазина

- `companies/flower_shop/company.json` — каталог (24 букета + 4 дополнения), доставка, оплата, правила, акции, правила эскалации.
- `companies/flower_shop/personas.json` — 30 персон: 20 хотят купить, 10 нет (тролль, конкурент, жалоба…).
- `companies/flower_shop/variants/*.json` — варианты для A/B: `{"name", "description", "patch"}`, где `patch` накладывается на `company.json` (списки заменяются целиком).

Все данные вымышленные.
